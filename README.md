# AO Studio — Акыл Ордо

Веб-приложение для создания, хранения, поиска и проведения интеллектуальных командных игр **«Акыл Ордо»**.
Три формата игры:

- 📘 **Классический** — вопросы разложены по категориям, каждый стоит 1 балл.
- 🎲 **Рандом** — без категорий, вопросы вперемешку, каждый стоит 1 балл.
- 🎯 **Стратегический** — категории и цена вопроса от 1 до 5 баллов, как в «Своей игре».

Балл задаётся только в стратегическом формате; в классике и рандоме он всегда равен 1.

| Слой | Технологии |
|---|---|
| Бэкенд | Django 6 + DRF, JWT (simplejwt), PostgreSQL / SQLite |
| Фронтенд | React 19 + Vite + TypeScript, Tailwind CSS 4, Framer Motion, Zustand, Axios, @dnd-kit, canvas-confetti, Hugeicons |

## Структура

```
backend/            Django-проект
  config/           настройки, корневые URL
  users/            пользователь, регистрация/вход/профиль
  rooms/            AO комнаты, категории, вопросы, сохранения, статистика
  game/             игровые сессии и команды
frontend/           React-приложение
  src/pages/        Главная, AO комнаты, Присоединиться, Профиль, Создать АО, игры (game/)
  src/components/   Layout, модалки, карточки, игровые компоненты
  src/store/        Zustand: auth, ui (тема/модалки), game
  src/lib/          api (axios + JWT), звуки (Web Audio), типы, утилиты
```

## Локальный запуск

**Быстрее всего (Windows):** дважды щёлкните `start.bat` в корне проекта. При первом запуске он сам создаст
окружение и установит зависимости, затем запустит сайт на http://localhost:8000.

Весь проект (сайт + API + админка) запускается **одной командой** `python manage.py runserver`.
Перед стартом она сама проверяет, менялся ли фронтенд, и при необходимости собирает его
(`npm install` при первом запуске + `npm run build`). Нужен установленный Node.js, но запускать npm вручную не нужно.

```bash
cd backend
python -m venv venv
venv\Scripts\activate            # macOS/Linux: source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo       # демо-пользователь и 3 примера комнат
python manage.py runserver
```

База данных берётся из `DATABASE_URL` в файле `backend/.env` (он не коммитится). Пример:

```
DATABASE_URL=postgres://ao_studio:<пароль>@127.0.0.1:5432/ao_studio
```

Чтобы создать базу в локальном PostgreSQL (от имени `postgres`):

```sql
CREATE ROLE ao_studio LOGIN PASSWORD '<пароль>';
CREATE DATABASE ao_studio OWNER ao_studio ENCODING 'UTF8' TEMPLATE template0;
```

Без `.env` / `DATABASE_URL` проект работает на SQLite (`backend/db.sqlite3`).

Откройте http://127.0.0.1:8000 — сайт, админка: http://127.0.0.1:8000/admin/.
Запуск без проверки фронтенда: `python manage.py runserver --skip-build`.

**Режим разработки фронтенда (необязательно).** Если активно правите React и хотите, чтобы изменения
появлялись мгновенно без перезапуска, параллельно запустите `npm run dev` в папке `frontend` и откройте
http://localhost:5173 — Vite проксирует `/api`, `/media` и `/admin` на Django.

Демо-вход: логин и пароль указаны в `backend/rooms/management/commands/seed_demo.py`.

## Вход через Google

1. https://console.cloud.google.com → создайте проект → «APIs & Services» → «OAuth consent screen»: тип External,
   название приложения, email поддержки; в «Test users» добавьте свои Google-аккаунты (пока приложение в режиме тестирования).
2. «Credentials» → «Create credentials» → «OAuth client ID» → тип **Web application**.
   В «Authorized JavaScript origins» добавьте: `http://localhost`, `http://localhost:8000`, `http://localhost:5173`
   (и домен сайта после деплоя). Redirect URI не нужны.
3. Скопируйте Client ID в `backend/.env`: `GOOGLE_CLIENT_ID=xxxx.apps.googleusercontent.com` — сервер перезапустится сам.
4. Открывайте сайт по **http://localhost:8000** (Google не принимает адрес `127.0.0.1`).

Новый пользователь создаётся автоматически (логин — из email, аватар — из Google). Если аккаунт с таким email
уже есть, Google привязывается к нему. Client ID не секретный; Client secret проекту не нужен.

## Админка

Django admin с темой Jazzmin. Открывается по `/admin`, а также с любой страницы сайта, если дописать `/admin`
к пути (например `/rooms/admin`). Там можно смотреть, добавлять, редактировать и удалять пользователей, комнаты,
категории, вопросы (с фото), игровые сессии и команды; на главной админки — статистика.

Создать или обновить администратора:

```bash
python manage.py ensure_admin --username <логин> --password <пароль>
```

**На Vercel администратор сам не создаётся** — этапа релиза у Vercel нет, команду нужно выполнить один раз
с локальной машины против боевой базы, так же как миграции:

```bash
vercel env pull .env.local
# DATABASE_URL взять из DATABASE_URL_UNPOOLED в .env.local
DATABASE_URL=<...> DJANGO_ADMIN_USERNAME=<логин> DJANGO_ADMIN_PASSWORD=<пароль>   python backend/manage.py ensure_admin
```

Команда создаёт администратора, а если он уже есть — обновляет пароль и права. Боевая база и локальная
независимы: администратор, созданный локально, в админку на сайте не пустит.

## Два сценария игры

- **Доска** (раздел «Доска») — ведущий проводит игру на экране или проекторе. Перед запуском он задаёт состав
  (сколько команд и игроков в команде) и время на вопрос; на доске появляются **код комнаты** и QR-код.
  Аккаунт участникам не нужен. С самого сайта к игре ведёт раздел **«Присоединиться»** в меню: там можно
  набрать код руками или навести камеру на QR-код с доски.

  **В игре телефон каждого участника, а не один на команду.** Сбор идёт так:

  1. первым по коду входит **капитан**: называет себя, команду и сколько их в команде;
  2. остальные входят по тому же коду, называют себя и **выбирают свою команду** из списка;
  3. капитан назначает, **кто пишет ответы** за команду, — с этого момента команда «готова»;
  4. ведущий видит готовность каждой команды и, когда готовы все, запускает игру. Кнопка «Начать игру»
     до этого заблокирована и показывает, скольких ждём; автостарт тоже ждёт готовности всех.

  В игре вопрос, таймер и поле ответа видит **только отвечающий** — он же выбирает клетку или карточку,
  когда ход его команды. У остальных телефон занят заглушкой «Телефон занят игрой»: подсказывают вслух.
  Капитану **всегда виден состав команды** со списком, из кого выбрать отвечающего. Пока открыт текущий
  вопрос, подменить его нельзя — это тянуло бы время, — поэтому выбор встаёт в очередь и вступает в силу,
  когда ведущий откроет следующий вопрос; в составе такой участник помечен как «следующий». Между
  вопросами выбор срабатывает сразу. Если намеченный успел вылететь из зачёта, замена не состоится. Ведущий видит ответы команд с подсказкой «совпадает», в классическом
  формате есть кнопка «Отметить совпавшие».
- **Одиночная игра** (кнопка «Начать АО» на главной) — поиск игры, ввод своего имени, и игрок сам открывает
  вопросы: сайт проверяет ответы и считает баллы. В конце — итог и работа над ошибками.

Создавать игры и запускать их может только зарегистрированный пользователь; участники на телефонах входят
по коду без аккаунта.

## Два языка интерфейса

Сайт переключается между русским и кыргызским — кнопки «РУС / КЫР» внизу меню, в верхней
панели на телефоне и на экране входа участника (туда заходят по QR с чужого телефона, и
меню сайта там нет).

Переводы лежат в `frontend/src/lib/locales/ky.ts`, а ключ словаря — **сам русский текст**:

```tsx
<h1>{tr('Итоги игры')}</h1>
```

Так в разметке остаётся живая фраза, а не код вроде `results.title`, и ни один перевод не
может «потеряться»: без записи в словаре выводится русский исходник. Подстановки — именованные:
`tr('Готовы {n} из {total}', { n: ready, total: teams.length })`, иначе при переводе
рассыпался бы порядок слов.

Функция называется `tr`, а не привычное `t`: буквой `t` в коде игры обозначена команда
(`teams.map((t) => …)`).

**Важно при правках:** `tr()` нельзя звать на уровне модуля — такое значение посчитается один
раз при загрузке и после смены языка останется на прежнем. Константы с текстом объявляются
функциями (`const weekdays = () => [tr('Пн'), …]`) или геттерами, как `FORMATS` в
`lib/utils.ts`. Смену языка подхватывает `App`: он держит ключ на дереве страниц, поэтому
экран пересобирается целиком и подписка на язык в каждом компоненте не нужна.

Содержимое, которое пишут сами пользователи — названия комнат, вопросы, ответы, имена
команд, — не переводится: это их текст.

## Профиль

Раскладка в две колонки, как на GitHub: слева карточка человека (аватар, логин, счётчики,
дата регистрации) — она остаётся на месте при прокрутке, справа лента того, что он сделал:

- **Созданные AO комнаты** — свои игры;
- **Сохранённые AO комнаты** — копии чужих, их правят как свои (см. «Сохранённые комнаты»);
- **Активность** — календарь на год, клетка на день: `GET /api/auth/me/activity/` считает
  созданные комнаты и проведённые игры (`components/ActivityCalendar.tsx`). Неделя начинается
  с понедельника, а не с воскресенья, как на GitHub;
- **История игр** — `GET /api/game/history/`: что за комната, когда, сколько команд и кто
  выиграл. Лобби, которое так и не началось, в историю не попадает.

Счётчик «создано AO комнат» считает только свои комнаты: сохранённые копии чужих игр идут
отдельной строкой, иначе число не сходилось бы со списком выше.

## Иконки

Загружаемые аватары приводятся к 512 px по длинной стороне (`backend/core/images.py`) и
разворачиваются по EXIF. Без этого снимок с телефона 3120×4208 браузер ужимал в кружок 120 px
и заметно мылил, да ещё и тянул по сети лишние три мегабайта на каждую отрисовку.

Набор — **Hugeicons** (`@hugeicons/react` + `@hugeicons/core-free-icons`). Он завёрнут в
`src/lib/icons.tsx`: компоненты там названы как иконки lucide, которые стояли раньше, и принимают
те же пропсы (`size`, `className`, `fill`, `strokeWidth`). Поэтому разметка страниц при переходе
не менялась — в каждом файле поменялся только источник импорта, а соответствие имён видно
в одном месте. Новую иконку добавляют туда же, одной строкой.

Значок формата игры живёт в `FORMATS` (`src/lib/utils.ts`) и рисуется компонентом
`components/FormatIcon.tsx`: книга — классический, кубик — рандом, сетка клеток — стратегический.

## Варианты ответа

У вопроса, кроме основного ответа, можно задать **другие принимаемые формулировки** —
кнопка «Добавить вариант ответа» в редакторе, до десяти штук. Нужны, чтобы в игре не спорили,
засчитывать ли «Бишкек» и «город Бишкек»: засчитываются все перечисленные.

Сверка одинаковая на сервере (`answer_matches` в `backend/game/live.py`) и в браузере
(`lib/answers.ts`): регистр, «ё» и знаки препинания не важны. По-прежнему работает и старый
приём — перечислить варианты прямо в поле ответа через «/», «;», «,», скобки или «или»;
такие списки разбираются и внутри дополнительных формулировок.

## Сохранённые комнаты

Чужую игру можно **сохранить себе** — кнопка с закладкой на карточке в «AO комнатах».
Сохранение делает личную копию со всеми категориями, вопросами и фотографиями: её видно
в профиле под своими комнатами, и править её можно как свою — менять вопросы, категории,
время. Оригинал автора при этом не меняется, а его правки до вашей копии не доходят.

Копия создаётся приватной. Повторное нажатие копию не плодит — кнопка ведёт на её
редактирование. Чтобы убрать сохранённую комнату, её удаляют как обычную свою.
Число на кнопке — сколько раз игру сохранили себе.

**Приватные комнаты** не показываются в списке: такую комнату находят, набрав её название целиком, или
открывают по прямой ссылке.

Устройства участников опрашивают сервер раз в 1,5 с (`/api/live/<код>/`) — серверные функции Vercel не держат WebSocket.

## Защита от списывания (античит)

В онлайн-режиме ведущий может включить **защиту от списывания** (по умолчанию включена, переключатель — в
модалке запуска). Идея: телефоны у участников **не отбирают** — вместо этого телефон каждого занят экраном
игры, и уход с него виден ведущему.

Как это работает на устройстве участника:

- после старта игра просит развернуться на весь экран; пока участник не вошёл, вопрос и поле ответа скрыты;
- браузер сообщает сайту, что страница ушла с экрана: свернули приложение, переключили вкладку, вышли из
  полного экрана, закрыли страницу (последнее — через `navigator.sendBeacon`, обычный запрос не успевает уйти);
- **первый уход — предупреждение**, второй — **участник вне зачёта**: отвечать и выбирать вопросы он больше
  не может. Если это был отвечающий, команда остаётся без ответов, пока капитан не назначит нового;
- когда вне зачёта оказываются **двое участников, с игры снимают всю команду**: ответы сервер больше не
  принимает, баллы заморожены, команда уходит в конец табло с пометкой «вне зачёта»;
- пока идёт игра, экран удерживается включённым через **Screen Wake Lock**. Без этого телефон гасил бы его
  сам через минуту покоя, страница ушла бы в `hidden`, и участник получил бы нарушение, ничего не сделав;
- выделение и копирование текста вопроса отключены, при попытке закрыть страницу браузер переспрашивает.

Ведущий видит всё на игровом экране: всплывающее уведомление о нарушении (со звуком), кнопка «Защита» внизу
слева открывает выбывших участников и снятые команды, предупреждённых, составы с пометками «капитан» и
«отвечает», журнал нарушений со временем и отметку «нет связи с устройством» (устройство молчит дольше 10 с).
Кнопки **«Вернуть участника в игру»** и **«Вернуть команду в игру»** снимают дисквалификацию и обнуляют
предупреждения; когда выбывших снова меньше двух, снятие с команды снимается само. В игре, запущенной с
доски, панель остаётся доступной и в режиме проектора — там это единственное устройство ведущего.

**Чего защита не делает.** Страница в браузере не может физически запретить свернуть себя или открыть другую
вкладку — это умеет только нативное приложение (режим киоска Android, гид-доступ iOS). Защита *обнаруживает*
уход с экрана и наказывает за него. Второе устройство рядом (чужой телефон, ноутбук) не определяется никаким
веб-приложением — против этого работают только правила зала и наблюдение ведущего. Поэтому первое нарушение
прощается: входящий звонок или уведомление тоже уводят страницу с экрана. Выключенный экран браузер не
отличает от переключения в другое приложение, поэтому гасить экран тоже считается уходом — Wake Lock нужен
именно для того, чтобы это не случалось само собой.

## Тесты

Бэкенд — встроенный раннер Django:

```bash
cd backend
python manage.py test
```

Раннер создаёт отдельную тестовую базу, поэтому с `DATABASE_URL` на локальный PostgreSQL он
требует у роли права `CREATEDB` (`ALTER ROLE ao_studio CREATEDB;`). Проще прогнать на SQLite:

```bash
DATABASE_URL=sqlite:///db.sqlite3 python manage.py test
```

Фронтенд — Vitest (окружение jsdom):

```bash
cd frontend
npm test          # один прогон
npm run test:watch
```

Тесты лежат рядом с кодом (`*.test.ts`). Покрыто то, от чего зависит счёт в игре:
`lib/answers.ts` — автопроверка ответа (она должна совпадать с `answer_matches` в
`backend/game/live.py`), `hooks/useAnticheat.ts` — предупреждение, выход из зачёта,
прощение ведущим и маячок при закрытии страницы, `lib/utils.ts` — очередь хода по номерам
команд, и `components/QrScanner.tsx` — разбор кода из QR (тест рисует настоящий QR и
прогоняет его через jsQR, без камеры).

На бэкенде покрыт сбор состава (капитан заводит команду, участники её выбирают, лимит мест,
назначение отвечающего и очередь на следующий вопрос) и античит: личные предупреждения, выход
участника из зачёта, снятие команды при двух выбывших, возврат в игру и запрет старта, пока не
готовы все команды, а также профиль: календарь активности (своё/чужое, граница года) и история игр
(лобби в неё не попадает, дисквалифицированная команда не становится победителем).

## API

Auth: `POST /api/auth/register/`, `login/`, `logout/`, `token/refresh/`; `GET /api/auth/me/`, `PATCH me/update/`, `DELETE me/delete/` (тело `{username}`),
`GET /api/auth/me/activity/` — календарь активности за год: `{from, to, total, days: {"2026-11-08": {rooms, games}}}`.

Комнаты: `GET/POST /api/rooms/`, `GET/PATCH/DELETE /api/rooms/{id}/`, `GET /api/rooms/my/`, `GET /api/rooms/saved/`, `POST /api/rooms/{id}/save/`,
`POST /api/rooms/{id}/questions/`, `POST /api/rooms/{id}/categories/`, `PATCH/DELETE /api/questions/{id}/`, `DELETE /api/categories/{id}/`,
`GET /api/rooms/categories-list/`, `GET /api/stats/`.

Фильтры списка: `search`, `fmt` (`classic|strategic|blind`), `qcount` (`5-10|10-20|20+`), `categories` (через запятую),
`show` (`all|mine|saved|available`). Параметр формата называется `fmt`, потому что `format` в DRF зарезервирован.

`POST /api/rooms/` и `PATCH` принимают комнату целиком с вложенными `categories[].questions[]` (или `questions[]` для слепого формата);
фото загружается отдельно: `PATCH /api/questions/{id}/` (multipart, поле `photo`).

Игра: `POST /api/game/start/` `{room_id, mode, anticheat, teams:[{name,color}]}`, `GET /api/game/{id}/`,
`GET /api/game/history/` — свои сыгранные игры с командами и победителем,
`PATCH /api/game/{id}/score/` `{team_id, delta|score}`, `PATCH /api/game/{id}/finish/`.

Участники (без аккаунта, по коду): `GET /api/live/{код}/` — состояние игры, свой состав и своя роль;
`POST /api/live/{код}/join/` — вход: `{name, team_name, size}` заводит команду (отправитель становится
капитаном) либо `{name, team_id}` присоединяет к уже созданной; `POST /api/live/{код}/answerer/`
`{participant_id}` — капитан назначает, кто пишет ответы; во время открытого вопроса выбор встаёт в
очередь на следующий (ответ содержит `queued: true`);
`POST /api/live/{код}/answer/` и `POST /api/live/{код}/pick/` — только от отвечающего.

Античит: `POST /api/live/{код}/violation/` `{kind}` — устройство участника сообщает об уходе с экрана
(`hidden|blur|fullscreen|left|lost`; токен устройства в заголовке `X-Team-Token` или в теле — для `sendBeacon`);
`GET /api/game/{id}/anticheat/` — сводка для ведущего с составами и нарушениями поимённо;
`POST /api/game/{id}/participants/{participant_id}/pardon/` — вернуть участника,
`POST /api/game/{id}/teams/{team_id}/pardon/` — вернуть команду целиком.

## Деплой (Vercel)

Весь проект живёт в одном проекте Vercel (`ao-studio`):

- **Фронтенд** — собирается из `frontend/` в статику (`frontend/dist`).
- **Бэкенд** — Django работает как Python-функция `api/index.py`; запросы `/api`, `/admin`, `/static` направляются туда (см. `vercel.json`).
- **База** — Neon Postgres из маркетплейса Vercel (переменная `DATABASE_URL`).
- **Файлы** (аватары, фото вопросов) — Vercel Blob (`BLOB_READ_WRITE_TOKEN`), см. `backend/core/storage.py`.

Переменные окружения проекта: `DJANGO_SECRET_KEY`, `DJANGO_DEBUG=0`, `DJANGO_ALLOWED_HOSTS=.vercel.app`,
`DATABASE_URL`, `BLOB_READ_WRITE_TOKEN`, при необходимости `GOOGLE_CLIENT_ID`.

Деплой идёт сам: репозиторий подключён к проекту Vercel (`vercel git connect`), и каждый пуш
в `main` собирается и уезжает в продакшн. Боевые адреса — `ao-studio-main.vercel.app` и
`ao-studio-jade.vercel.app`.

Выложить вручную, не дожидаясь пуша:

```bash
vercel deploy --prod
```

Миграции выполняются с локальной машины против базы Neon:

```bash
vercel env pull .env.local
# DATABASE_URL взять из DATABASE_URL_UNPOOLED в .env.local
python backend/manage.py migrate
```

Для входа через Google добавьте домен сайта в «Authorized JavaScript origins» и задайте `GOOGLE_CLIENT_ID` в Vercel.
